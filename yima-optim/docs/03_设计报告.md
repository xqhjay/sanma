# 奕码性能优化 · 设计报告

> 版本：奕码 1.2 优化版（小码音托不变 · 大码重排 · 拆分 100% 保真）

## 1. 摘要

在不改变奕码任何拆分与字根小码（音托）的前提下，仅重排 272 个主根的大码字母指派，
并对二码字做精确最优指派，三项核心指标**全面严格超越**官方 1.2 基线：

| 指标（字劫测评·出简重排除全码口径） | 官方 1.2 基线 | 优化版·均衡（主推） | 变化 |
|---|---|---|---|
| **M1**：前1500高频字二码字总数 | 563 | **661** | **+98（+17.4%）** |
| **C1500**：前1500出简重码数（硬约束=0） | 0 | **0** | 保持 |
| **M2**：1501~3000 出简重码数 | 5 | **0** | **−5（清零）** |
| **M3**：前6000 出简重码总数 | 324 | **300** | **−24（−7.4%）** |

另交付两个风格化变体（极速版 M1=676 满覆盖 / 低重版 M3=223），三者构成 Pareto 前沿
上的三个代表性交付点，用户可按偏好选用。全部结果均通过与 chs.hertz.ltd 前端逻辑
一致的复现测评器端到端验证（官方表逐项校准一致）。

**全部约束满足**：前1500出简重=0；主字根小码音托完全不变（合规率 87.5% 原样保持）；
字根集不增不减（归并组 272 ≤ 300）；拆分结构与官方完全一致（8230/8230 = 100%）。

## 2. 优化对象与口径

### 2.1 奕码方案

奕码是"大码乱序、小码音托"的字根双编码三码形码方案：

- **字根双编码**：每根 = 大码 + 小码。大码乱序分布在 26 字母；小码按读音记忆（音托）。
- **两种打字方式**（同一套字根编码，两种顶功节奏）：
  1. **四二顶**：无一简。输入第 4 码时顶前二码对应的字上屏；三码字空格上屏。
  2. **三定**：含一简（26）与二简（676），一/二简字空格上屏，单字最多三码。

### 2.2 测评口径（字劫测评，出简重-排除全码）

- 每字取**最短码**为实际使用码；出简重(排除全码) = 最短码相同且频序更靠后的字数。
- 二码字的最短码是唯一的二码，与任何三码字不构成出简重——**二码字是"免费"的冲突消解器**。
- 三项指标：M1（前1500二码字数）、M2（1501~3000 出简重）、M3（前6000 出简重总数）。

## 3. 方法论

### 3.1 官方拆分 100% 保真（优化的地基）

从 sanma 仓库 git 历史恢复官方《奕码拆分.txt》（8230 字全量根序列），配合
`奕码_小泥巴_1.2.yaml` 的 272 主根 + 277 变体映射（含冖=['c',宀[1]] 之类的双编码列表值），
**逐字复现官方三码 8230/8230 = 100%**。编码状态机：

| 字型 | 全码 | 二码前缀 | 例 |
|---|---|---|---|
| 单根字 | 大+小+小 | 大+小 | 回 dh→dhh |
| 两根字 | 大₁+大₂+小₂ | 大₁+大₂ | 相 木sm+目fm→sfm |
| 3+根字 | 大₁+大₂+大末 | 大₁+大₂ | 就 享字头cg+小hx+尤dy→chd |

拆分、字根集、小码全部保持官方原样 ⇒ **零记忆迁移成本**（老用户只需重记大码布局）。

### 3.2 精确冲突模型（端到端验证通过）

- **S（二码字集）**：每个二码前缀至多 1 字，条目 = 该字全码的前缀。
- **出简重(排除全码) = 非 S 字中，全码与频序更早的非 S 字相同者**。
- 用官方码表对此模型做了端到端验证：模型预测 = 字劫测评复现输出（逐项一致，
  563/0/5/324 完全复现）。

### 3.3 二码指派的精确可分解性（本优化的核心引理）

**引理**：全码 = 前缀字母对 + 第三码，故**同全码 ⇒ 同前缀**，全码碰撞组完全落在单一前缀内。
因此各前缀的二码字选择互相独立，全局目标可按前缀精确分解：

```
选 S=x 的全局变化 = w_M1·[rank(x)<1500] + relief(x)
relief(x) = w(x)              若 x 在其全码组内非组首（自身被解放）
          = w(组内第2位)       若 x 是组首且组>1（第2位被解放）
          = 0                 若单字组
```

每前缀取 value 最大者即为**任意线性权重下的精确最优指派**（w15=10⁶ 保证前1500优先，
等效硬约束 C1500=0 对可化解冲突成立；不可化解的结构冲突由大码搜索用 10⁶ 惩罚消除）。
该精确指派替代了官方的启发式选择——仅此一项，官方大码下即可把出简重压到
官方码表实际值以下（官方指派本身留有可优化空间）。

### 3.4 精确 Pareto 前沿（超越线性标量化）

线性权重指派只能命中前沿上的"支撑点"。为完整刻画可达边界，实现了**精确前沿计算**：

1. 对每个二码前缀，穷举其全部候选 S 字，得到该前缀的 (M1, M2, M3) 增量向量集合
   （C1500=0 作为硬约束在每前缀内先行过滤）；
2. 逐前缀做 3 维支配过滤（Fenwick 树 O(n log n)），再做 Minkowski 和合并，
   得到该大码表可达的**精确 Pareto 前沿**（数千点）；
3. 跨大码表取并集再过滤 → 全局前沿。

据此锁定了三个代表性交付点（见 §6），并确认了各区域的最优可达权衡。

### 3.5 大码模拟退火

- **状态**：272 主根 → 26 大码字母（均值 10.5 根/字母；软惩罚单字母 >16 根保持均衡）。
- **目标**：`score = w₁·(676−M1) + 10⁶·C1500 + w₂·M2 + w₃·M3 + 5·Σ超载`
  （多组权重并行：M1 极大化 / 均衡 / M2M3 救济优先 / 中间档，从不同起点搜索）。
- **移动**：冲突驱动（55%，从当前冲突字的根中选根、采样候选字母取最优）+
  随机换码（20%）+ 根换位（25%）。
- **退火**：两阶段（高温探索 → 低温精修），后接逐冲突穷举精修（单根 26 字母 + 同字母根换位）。
- **产出**：多个大码布局 → 权重扫描 + 精确前沿 → 全局 Pareto 前沿 → 选定交付点。

## 4. 主字根小码音托规律（完全保持官方）

小码 = 官方音托，**一个字母都不改**。272 主根的音托分类（用 pypinyin 全量核对）：

| 类别 | 数量 | 占比 | 规则 | 例 |
|---|---|---|---|---|
| **声母托** | 201 | 73.9% | 小码 = 声母首字母；zh/ch/sh → z/c/s | 是sh→s、木m→m、去q→q |
| **韵母托** | 31 | 11.4% | 小码 = 韵母首字母（声母已占或零声母） | 子zi→i、足zu→u、者zhe→e |
| **ü→v 韵托** | 6 | 2.2% | ü 用 v 表示（拼音输入法惯例） | 雨yu→v、鱼yu→v、羽yu→v |
| **数字根** | 6 | 2.2% | 数字 1~6 本身作根（键盘数字行） | 1、2、3、4、5、6 |
| **部件/形托** | 28 | 10.3% | 无读音部件按形/约定 | 冂k、匚k、囗k（包围形→k） |

**易记率（声母+韵母+ü→v）= 238/272 = 87.5%**，含数字根 244/272 = 89.7%。

声母托分布规整（22 根 sh→s、18 根 g→g、17 根 y→y、16 根 j→j……），
多音字取常用音（长 cháng→c、乐 yuè→y）。优化后所有字根的小码与官方完全一致，
**音托记忆零迁移**。逐根明细见《字根编码表_均衡.txt》与《主字根音托读音规律.txt》。

## 5. 大码布局（优化产物）

大码是"乱序"设计——字母与根的对应本无语义约束，这正是重排的自由度所在。
优化后的布局原则：

1. 高频根对（高频字的首二根组合）尽量分散到不同字母对 → 前1500 覆盖更多二码前缀；
2. 碰撞根组（产生相同三码的根组合）错开字母 → 消解跨签名全码碰撞；
3. 单字母根数 ≤16（软约束）→ 保持各字母键位均衡、利于手感。

均衡方案（主推）的字母负载（根数/字母，共 272 根）：

```
a:12  b:7  c:13  d:9  e:11  f:12  g:13  h:9  i:13  j:5  k:13  l:8  m:8
n:10  o:9  p:14  q:12  r:12  s:7  t:10  u:12  v:9  w:11  x:10  y:10  z:13
```

（最大 14、最小 5、平均 10.5——分布均衡，无过载键位。）

完整布局见 `output/字根编码表_均衡.txt`（按字母序，含每根拼音与音托依据）。

## 6. 性能验证（字劫测评端到端）

用与 chs.hertz.ltd 前端逻辑一致的复现测评器（官方表逐项校准一致）对新表评测：

| 表 | M1 | C1500 | M2 | M3 | 6000内二码 | 6000内全码重 | 缺字 |
|---|---|---|---|---|---|---|---|
| 官方四二顶 1.2 | 563 | 0 | 5 | 324 | 676 | 684 | 0 |
| **优化·均衡（主推）** | **661** | **0** | **0** | **300** | **676** | **671** | 0 |
| 优化·极速 | 676 | 0 | 5 | 375 | 676 | 727 | 0 |
| 优化·低重 | 626 | 0 | 0 | 223 | 675 | 594 | 0 |

### 6.1 三个交付点的定位（Pareto 前沿代表点）

- **均衡（主推）661/0/300**：三项指标全面严格优于官方。前1500 二码字覆盖 44.1%
  （661/1500，官方 37.5%）；1501~3000 出简重清零；前6000 出简重再降 7.4%。
- **极速 676/5/375**：M1 满覆盖（676/676 = 理论上限，前1500 二码字覆盖 45.1%），
  M2 与官方持平，代价是 M3 +51。适合追求极限跟打速度的用户。
- **低重 626/0/223**：M3 大降 31%（324→223），全码重码也从 684 降到 594。
  适合重码敏感、愿意让出 35 个二码名额的用户。

M2=0 线上 M1↔M3 的可达权衡为连续谱：626/223 → 643/266 → **661/300** → 668/352
（M1 每换 1 字，M3 约换 1 字）；再往上 M1=676 满覆盖时 M2 回升至 5、M3=375。
主推点 661/0/300 是"三项全面严格优于官方"区域内的最大 M1 点。

### 6.2 优化机理

1. **指派层**（精确最优 vs 官方启发式）：每前缀选"解放冲突最多"的字作二码字；
2. **大码层**（SA 重排）：272 根的字母分布决定 8230 个三码的碰撞结构，
   冲突驱动搜索直接以 M1/M2/M3 为目标；
3. **权衡控制**：M1=676（满覆盖）会把全部二码名额给前1500字，3000~6000 字失去救济通道；
   精确前沿给出 M1↔M2↔M3 的完整权衡边界，交付点按用户优先级（M1 > M2 > M3）选取。

### 7.1 方案文件（小泥巴平台 YAML）

与官方 `奕码_小泥巴_1.2.yaml` 同构的完整方案文件，唯一改动是
`form.mapping` 中 272 个主根的大码字母（小码、变体归并、元素定义、拆分规则、
编码状态机、简码方案等全部原样保留）。生成后做了三重校验：

1. **根编码**：272 根经引用解析后的生效编码与优化指派逐一相符（0 不符）；
2. **变体**：277 个形近变体全部保持官方指向（含 \uf001→\ue41e→彡 链式引用）；
3. **逐字全码**：按 YAML 重建的 8230 字三码与四二顶码表逐字一致（8230/8230）。

使用：码表格式与官方完全一致（`字\t码`，UTF-8，CRLF），可直接导入 Rime 等平台

## 8. 局限与展望

- 大码重排需重新记忆 272 根的字母位置（一次性成本；小码与拆分不变）；
- M3 的残余冲突主要来自 3000~6000 低频段的跨签名碰撞，进一步压缩需增删字根
  （会破坏 100% 拆分保真）或接受更低的 M1；
- 后续可用更大步数 SA / 分支定界继续逼近结构下限（理论下限 = 25 组同签名冲突，均可二码化解）。
