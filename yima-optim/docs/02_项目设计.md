## 2. 编码规则（官方逆向，100%验证）

- 字根编码 = 大码 + 小码；**小码 = 官方音托，一律不变**（音托合规率原样保持）。
- 双编码列表值根（冖=cb、6=wi 等）按 `[大分量, 小分量]` 解析，分量可为字母或 `{element,index}` 引用。
- 全码状态机（8230/8230 验证）：

| 字型 | 全码 | 二码前缀 |
|---|---|---|
| 单根字 | 大+小+小 | 大+小 |
| 两根字 | 大1+大2+小2 | 大1+大2 |
| 3+根字 | 大1+大2+大末 | 大1+大2 |

- 二码条目 = 该字全码前缀（官方 676/676 验证），四二顶输入第4码顶前二码字上屏。

## 3. 精确冲突模型（端到端酸测通过）

- **S**（二码字集）：每前缀 ≤1 字。S 字最短码=唯一二码 → 无冲突；其全码让渡同组字 → **指派零副作用**。
- **出简重(排除全码)** = 非S字中全码与频序更早非S字相同者（文件按频序排列）。
- M1 = |S∩top1500|；C1500/M2/M3 = 各频段出简重；结构冲突组 25 组全为 size2 → 均可由 S 化解。
- 官方大码 + 智能指派 = M1 608 / C1500 0 / M2 24 / M3 351（指派层已验证优于官方 563/0/5/324 之 M1）。

## 4. 搜索设计

**状态**：`big: 272根 → 26字母`（均值 10.5 根/字母，无硬性容量约束，仅软惩罚 >16）。

**目标**（每步全量重算，numpy 向量化 ~2ms）：

```
score = 3000 × (676 − M1)      # M1 缺口 (用户第一优先)
      + 10⁶  × C1500           # 硬约束: 前1500出简重必须=0
      + 200  × M2              # 1501~3000 出简重
      + 20   × M3              # 前6000 出简重
      + 5    × Σ max(0, 每字母根数−16)
```

**二码指派（评估内嵌，两阶段 relief 贪心）**：
1. 各前缀在 top1500 候选中选 relief 最大者（relief=该字离池解放的冲突权重：
   组内非首位→自身权重；组首且组>1→第二位权重；单字组→0）；
2. 未覆盖前缀在其余字中选 relief 最大者。
   relief 权重: 前1500=10⁶, 1501~3000=200, 3000~6000=20。

**移动**：
- 冲突驱动（60%）：从当前冲突字涉及的根集合（R1/R2/R末）中选根，随机换字母——直击碰撞；
- 随机换码（20%）+ 交换两根（20%）：维持全局多样性。

**退火**：两阶段（高温 200→2 探索，低温 8→0.15 精修），各 6 万步；conflict 缓存每 400 步刷新。

## 5. 三定码表生成

- 一简（26）：每字母 l → 码以 l 开头的最高频字（与官方规则一致）。
- 二简（676）：四二顶二码字集；若该字已是一简，顺延该前缀次高频字。
- 全码：与四二顶一致（8230）。

## 7. 验证方案

1. `src/evaluator.py`（字劫算法复现，官方表酸测一致）对新四二顶表评测，输出 M1/M2/M3 与基线对照；
2. 结构校验：前1500出简重=0；676 二码恰为各字全码前缀；三定一简/二简无重叠冲突；
3. 一致性校验：新表全码与官方拆分→编码状态机输出 100% 一致（拆分不变，仅大码变）；
4. 约束校验：归并组 272 ≤ 300；小码与官方完全一致（音托不变）。
