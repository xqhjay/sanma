# 奕码性能优化 · 可行性分析报告

> 目标：在不违反硬约束的前提下，优化三项性能指标（字劫测评口径，排除全码模式）
> - **M1** = 前1500高频字二码字总数（基线 **563**）
> - **M2** = 1501~3000 出简重码数（基线 **5**）
> - **M3** = 前6000 出简重码总数（基线 **324**）
> - **硬约束**：前1500 出简重码数保持 **0**；主字根小码音托；形近归并；归并组 ≤300

---

## 1. 基线复现（已完成）

用官方 1.2 版四二顶码表 + 科测6000字频表，完整复现字劫测评算法（`src/evaluator.py`）：

| 指标 | 官方值 | 复现值 | 结论 |
|---|---|---|---|
| 前1500二码字 M1 | 563 | **563** | ✅ 一致 |
| 前1500出简重 | 0 | **0** | ✅ 一致 |
| 1501~3000出简重 M2 | 5 | **5** | ✅ 一致 |
| 前6000出简重 M3 | 324 | **324** | ✅ 一致 |

## 2. 指标机理分析（核心发现）

### 2.1 码表结构（已验证）

- 四二顶表 = **676 个二码字**（每 2 码前缀恰 1 字）+ 8230 个三码全码。
- 每个二码字的三码全码必以其二码为前缀（676/676 验证成立）——即**二码字 = 该前缀候选中选出的代表字**。
- 三定表 = 26 一简 + 676 二简 + 8230 三码，其中二简与四二顶二码 650/676 相同（26 个差异恰为一简字让位）。

### 2.1b 官方拆分表逆向（决定性突破）

从 sanma 仓库 git 历史恢复出官方《奕码拆分.txt》（8230 字全量根序列），配合 repertoire 根名映射与
双编码列表值解析（冖=['c',宀[1]]=cb、6=[5[0],'i']=wi），**8230/8230 = 100% 复现官方三码**
（`src/official_split.py`、`src/prepare.py`）。编码状态机：

| 字型 | 全码 | 二码前缀 |
|---|---|---|
| 单根字 | 大+小+小（回 dh→dhh） | 大+小 |
| 两根字 | 大1+大2+小2（相 木sm+目fm→sfm） | 大1+大2 |
| 3+根字 | 大1+大2+大末（就 享字头cg+小hx+尤dy→chd） | 大1+大2 |

拆分保真度由 94.5%（oracle 反推）提升至 **100%**（官方原表），优化建立在完全忠实的结构数据上。

### 2.2 M1 的决定因素：前缀覆盖 + 指派次优

- 全码前两码（前缀）由**首根大码、次根大码**（多根字）或**大码+小码**（单根字）决定。
- 前1500字在 676 个前缀上的分布：**只占 608 个前缀**；官方 676 个二码字中 **166 个不是该前缀下最高频的字**。
- **仅修指派**（不动官方大码）：M1 = 563 → **608**（+45），C1500 保持 0（已验证）。
- **理论上限 676**。前1500字的不同（首根,次根）有序对有 **1164 个**——供给远超 676，
  通过大码重排铺满 676 格组合可行（SA 已实证达成 M1=676）。

### 2.3 M2/M3 的决定因素：三码全码碰撞（精确机理）

- **出简重（排除全码）的精确定义**：非二码字中，全码与频序更早的非二码字相同者。
  二码字的最短码是唯一的二码，且其全码让渡给同组字——**二码指派零副作用、纯收益**。
  官方即用此机制解决结构冲突：人=kr(二码)/入=krr(全码)/从=kkr(两根字)，三字全无冲突。
- **结构性冲突极小**：同签名（字型,根序列决定相同全码）组前6000仅 **25 组且全部 size=2**
  （人/入、我/找、前/剪、投/段等）——每组一字取二码即可完全化解 → **结构下限 = 0**。
- 官方 324 的碰撞主体是**跨签名碰撞**：不同根结构因共享大码字母而落入同一三码。
  这由 272 根在 26 个大码字母上的分布决定，**正是大码重排的直接优化空间**。
- 码空间 26³=17576，前6000非二码字约 5400，平均负载 0.31/格，压缩余地大。
- **关键权衡**：M1=676 时全部前缀归前1500字，3000~6000 字失去二码救济通道，
  跨签名碰撞须完全靠大码消解；官方 M1=563 留出 113 个二码用于救济低频冲突字。
  SA 目标函数需统筹（M1 缺口 3000/字、M2 200/字、M3 20/字、C1500 硬约束 10⁶/字）。

### 2.4 音托与字根集现状（约束可行性）

- 270 主根全部可注音；小码音托合规率：**声母托 74% + 韵母托 11% = 86%**（小码字母 ∈ 拼音字母）。
- 典型规律：sh→s、ch→c、y→y/ü(v)、w→u/w、g→g、m→m 等（详见设计报告）。
- **本方案保持小码完全不变** → 音托合规率 100% 保持，无记忆迁移成本。
- 归并组 270 ≤ 300 ✅（不增删字根，无组数风险）。

### 2.5 拆分保真度

- **官方拆分表 100% 逆向成功**（见 2.1b）：272 主根 + 277 变体，8230 字全量根序列与官方三码完全一致。
- 自研 ChaiSans 拆分引擎（`src/chaisplit.py`）作为规则解释器保留，用于拆分表的美观化展示与校验。

## 3. 优化路径与预期收益

| 路径 | 动作 | M1 | M2 | M3 | 风险 |
|---|---|---|---|---|---|
| P1 指派优化 | 每前缀二码字选最优（不动大码） | 563→608 | 5→24 | 324→351 | 无（已验证） |
| P2 大码重排 | 272根大码 SA 搜索 + 冲突感知指派 | →**676** | →下降 | →取决于SA | 拆分不变，仅编码变 |
| P3 字根增补 | 成字根填空前缀（备选） | 持平676 | 持平 | 持平 | 需重拆+新音托，放弃100%保真 |

**推荐 P1+P2**：不增删字根（归并组数 272 不变 ≤300）、小码音托原样保留（合规率不变）、
拆分结构 100% 不变，只重排"大码→字母"的对应关系（大码本就是乱序设计，重排不破坏任何设计原则），
三项指标同时改善，且硬约束（前1500出简重=0）作为 SA 硬性惩罚项保证。
SA 已实证 M1=676 可达；M2/M3 的收敛深度取决于搜索时长与冲突驱动移动效率。
